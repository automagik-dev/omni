## Problem

Omni reaches agents only by calling them (the dispatcher and `call_agent`), so an agent of any other harness cannot
pair with Omni as a principal and receive, asynchronously and outbound-only, just the events it owns. The owner wants
the old path kept and extended, with no per-framework code in Omni. Three live exposures sat on the same surfaces at
`ee5753234`: pull ignored the caller's instance clause, durable consumers crossed tenants, and unbinding an agent's last
instance widened its key to every instance. All three fixes have merged on dev: fix 3 as #1462 (`db318c533`) and its
review follow-ups #1469 (`663f0a08f`). Two residues of fix 3 remain. Its start-up key repair stops the boot on any
error, and the owner chose that it log and keep running (R13-2). Route writes provision no key, so an agent named only
by a route can be silenced. The GitLab connector and the swarm's Omni intake both wait on this design, and the
connector also waits on slice 7's benchmark.

All facts below are read at `origin/dev` `663f0a08f`, as the DRAFT's round 15 records them. A cite marked
`ee5753234` describes the code before the fixes. #1465 (`8885c362f`) is the baseline for the `connector.*`
reservation, and #1468 (`562a335f4`) adds migration `0092_connector_ingress.sql`, the last migration at `663f0a08f`.
The C0 to C20 labels are the conditions in the DRAFT's Scope ratchet: C0 to C14 come from the council in
`.genie/brainstorms/gitlab-sdlc-connector/council-paired-agents-2026-11-01.md`, and C15 to C20 come from owner answers.

## Approach

Extend Omni instead of replacing it. An agent declares what it consumes once, in its manifest `accepts`, and a per-agent
delivery mode picks the compile target. Call mode compiles to today's `call_agent` automations. Subscriber mode
compiles to agent-owned durable consumers, which the agent drains by pull, long-poll or SSE with its own narrow child
key and acts on through outbound verbs. Isolation comes first: the three live exposures shipped as fixes ahead of the
design, and each slice adds ownership, credentials, emission guards and then the compile, in the council's order.

**Groups.** Each group is one wish or one PR, in this order. Fixes 1 to 3 and follow-ups A and B ship unflagged and
always on, and slices 2 to 7 each ship behind their own flag:

**What merged for fix 3, and what follows it.** Fix 3 merged in a shape that differs from the earlier design in three
ways, and the owner settled each. A revoke does not rename the key, and the untenanted lookup takes only active system
keys, newest first: the owner accepted both as merged (R13-1), so a hand-made `agent:` key is never used for dispatch
and `doctor` lists it. The start-up repair stops the boot on any error: the owner chose that it log and keep running
(R13-2), which is follow-up A. The merged route writes provision no key and the repair reads bindings only, so an agent
named only by a route can be silenced; follow-up B keeps the reviewed design's promise that routed instances get keys.
`doctor`'s agent read did not merge with fix 3, and it ships with follow-up A, whose `doctor` line needs it.

**Alternatives considered.**
- A per-`accepts`-entry mode lost to a per-agent mode, because the owner set the mode per agent.
- Unbinding the agent on a switch lost to a dispatcher mode check (R4-1), because unbinding drops the binding's side
  effects.
- Skipping at run time in `call_agent`, or refusing the switch, lost to report-only `doctor` lines for hand-written rows
  (R7-1), because either would change approved behaviour (C7 or R3-1).
- Reading a mode key from the manifest lost to an `agents` column: the dispatcher already re-selects that row on every
  message, so no cache is needed.
- A grant clause on `metadata` jsonb lost to indexed provenance columns, because metadata is unindexed and absent on
  most instance-less producers.
- Letting an agent's own key write its grants lost to a grants table written only at pairing (R13-3): a self-granting
  agent could subscribe itself to another team's connector, so the grant would isolate nothing.
- Leaving keys already widened untouched lost to revoking and re-provisioning them (R11-1): before the fix a re-bind
  narrowed such a key back, and leaving them drops that repair.
- Stopping the boot on a repair error, as merged, lost to failing open (R13-2): one odd key row would keep every channel
  down, while failing open leaves only the exposure that existed before the upgrade, reported by `/health` and `doctor`.
- Renaming every revoked key lost to the merged revoke (R13-1): the lookups skip revoked keys, so the rename is not
  needed.
- Leaving route writes alone, with `doctor` telling the operator to bind the instance to the routed agent, lost to
  follow-up B (reviewer HIGH-1): binding moves the instance's default agent, and any later unbind would strip the
  instance again.
- Revoking hand-made `agent:` keys with the widened ones lost to listing them in `doctor`: someone holds their secret,
  and a key made with `null` on purpose cannot be told from one the bug widened.

## Simplicity Case

- **Simplest complete design:** one `accepts` declaration, one mode column, and two compile targets that already
  exist in kind (automations and durable consumers). The guarantees are added as ownership, key, stamp and grant rows
  on existing tables, plus one grants table.
- **Added machinery:** each mechanism has a present requirement behind it.
  - The provenance stamp: C2 grants and C5 filtering need an indexed source.
  - The grants table: R13-3 needs grants stored apart from anything the agent's key can write.
  - The agent-owned scan: R2-1 allows matched rows only.
  - The causation depth column: R4-3 sets depth 5, and no depth exists to reuse.
  - The one-transaction switch: today's reconcile autocommits outside a tenant scope and would leave both modes live.
  - The cutover instant: an event buffered across a switch must go exactly one way.
  - The `doctor` agent read: `GET /keys` stops at 100 silently.
  - The send idempotency key: C9 requires idempotent actions under at-least-once delivery.
  - The degraded reason for a failed repair: R13-2 needs the failure visible, and it reuses `/health`'s existing
    degraded pattern instead of a new surface.
  - Route writes as key writers: under R13-1 both dispatcher lookups need an active system key, so a route-named agent
    needs one on its routed instance (follow-up B).
- **Deferred until measured:** how globs are served on agent-owned consumers (a namespace column or a per-type
  merge), chosen after C13 measures. A union view over an agent's several consumers waits for a measured need.
- **Complexity removed:**
  - No multitenant path (R2-2), external id (R2-4), media route (R4-4) or typed action grants (R1-3).
  - No pause or dead-letter past the backlog limit (R3-4).
  - No jsonb index (R3-3).
  - No refusal at automation write or run time (R7-1).
  - No dispatcher cache, and no rename on revoke (R13-1).
  - No grant-writing route or CLI command (R13-3).
  - No revoke of hand-made `agent:` keys, which `doctor` reports instead (R11-1).
