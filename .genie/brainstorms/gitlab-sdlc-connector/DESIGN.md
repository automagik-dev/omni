## Problem

GitLab lifecycle events on `khal/brain` (issues, pushes, merge requests, review notes, CI failures, merges, tags,
releases, deployments) reach squad captains only when someone relays them by hand, because the project has no webhooks
and Omni cannot take GitLab's single multiplexed hook URL and turn it into typed events. This matters because Omni's
connector path today fans a target-less `connector.event` out to every tenant's automations, has no stream subject for
`connector.>` in the repository, and lets any publisher that names a `connector.*` type pose as the provider, so the
fix is an Omni ingress change before it is a GitLab package.

## Scope

Delivery order (Settled R3-2, R5-1): **slice 1** now; **slices 2 and 4** after slice 1 merges and only once the
paired-agent delivery minimum is merged and live on <internal-host>; **slice 3** (captain delivery) is built in
`.genie/brainstorms/paired-agents/`. The migration of signed webhook sources into connectors, which earlier rounds
designed here as slice 5, is designed in its own `signed-source-migration` brainstorm (Settled R11-1, R11-2).

## Approach

**Slice 1 changes the ingress, not the provider.** A connector gets one ingress URL, so one GitLab hook covers every
category. The SDK's `parseDelivery` returns a typed name under `connector.{provider}.*`; the ingress matches it against
the connector's `'connector'` subscriptions (event glob plus exact-match filters, target optional). On a match it writes
one journal row keyed `connector:{connectorId}:{providerEventId}` carrying every matched subscription id, publishes it
on a stream that holds `connector.>`, and fires each named target automation once: a targeted automation's trigger is
the exact typed name, and the row lists its targets in `targetAutomationIds[]`, which the D7 gate checks by membership
(Decisions #19). The ingress is the only publisher of a `connector.*` type: the bus refuses one on every other path,
and a retried or replayed `connector.*` event takes its routing from the ingress-written journal row, never from a
stored payload, so no automation, route or old dead letter can forge a row or its target list (Decisions #22, #23). On
no match it writes nothing but the connector's unmatched counters. A target-less subscription is how a category opts
into the journal for consumers; the D7 gate, widened to every `connector.*` type, keeps it from firing any automation,
and the no-target guard lands before the target becomes nullable, because today's target-less branch fires every
enabled `connector.event` automation of every tenant. ClickUp keeps its per-subscription route, its `'subscription'`
rows and its `connector.event` rows unchanged beside the new route. The SDK rule that lets a connector declare no
actions and hold only a hook secret lands here too, so slice 1 is proven on the shape `gitlab` will have.

**Slices 2 and 4 wait for delivery.** The `gitlab` connector is an events-only package on slice 1's ingress. It and the
measurement start after slice 1 merges and the paired-agent delivery minimum is merged and live: the tests of C0, C1,
C2 with a `connector.gitlab.*` row, C3, C4, C8 and one C12 drain, each checked on <internal-host> by an authenticated
probe. C0 was last seen in progress, not live, so the gate is not yet met. Agents receive `connector.gitlab.*` rows
through their durable consumers; agent manifests are not changed.

**Signed webhook sources stay where they are.** Their migration into connectors is designed in its own
`signed-source-migration` brainstorm (R11-1). Until it lands, signed webhook sources keep working unchanged beside
connectors, and this design refuses no new one, because no connector can take a GitHub sender yet.

**Alternatives considered and why they lost.**

- One GitLab hook per category, each pointing at a per-subscription URL: keeps today's one-key rule but multiplies
  hooks and secrets and leaves the fan-out and stream gaps; Settled R3-1 chose one URL per connector.
- A `gitlab.*` or `custom.gitlab.*` namespace: the first needs a registry member, stream and persistence subscriber per
  provider, the second collides with paired-agent C5 and is forgeable through `/events/trigger`; R3-1 chose
  `connector.gitlab.*`.
- Journaling every verified delivery: keeps push payloads (commit messages, author emails) nobody subscribed to; R4-1
  chose matched only.
- A dispatcher on the owner's Mac with `hc send`: an unowned consumer outside Omni; R3-4 and R1-3 send delivery through
  paired agents.
- GitLab test hooks for the zero-event categories: GitLab cannot send a deployment test, fails a release test without a
  release, and replays the latest pipeline or job with its real status; R6-1 chose real objects.
- Migrating signed webhook sources in this design: the round 10 review found GitHub's action-bearing types have no
  single exact new name and a `connector.*` `accepts` entry loses its targeted subscription on manifest recompile; R11-1
  moved the migration to its own brainstorm and dropped the manifest change.
- Telling the two subscription kinds apart by inference (a NULL secret or a typed-name prefix): an explicit `ingress`
  column with a CHECK makes the route a stored fact, and existing ClickUp rows need no rewrite.

## Simplicity Case

- **Simplest complete design:** one ingress route per connector, typed names in the existing `connector.` namespace (no
  new event namespace, no new persistence subscriber), counters as columns on the connector row, and an events-only
  GitLab package with no API token and no actions.
- **Added machinery:** the connector-keyed tenant lookup, policy and trigger (a per-connector URL has no subscription id
  to derive a tenant from); the `connector.>` stream subject (publishes fail without it); a `publishConnector` bus method
  beside a `connector.*` refusal in `publishGeneric` and `emit_event` (the gate trusts a row's target list, so only the
  ingress may write one); the retry-time provenance check on `connector.*` dead letters (stored dead letters, including
  ones written before slice 1, would otherwise carry a chosen target list); the `ingress` column and its CHECK (two
  routes share one table, and a `'connector'` id must not resolve on the per-subscription route).
- **Deferred until measured:** automation trigger globs, only if exact-name targeted subscriptions prove insufficient;
  typed GitLab actions, with their own scoped grants, in a later actions slice; a schema gate over `connector.*`, only
  when a connector needs one (the migration brainstorm decides it for migrated sources).
- **Complexity removed:** the cross-tenant target-less fan-out; dual-publish and double acks; payload storage for
  unmatched deliveries; a GitLab token in Omni; a Mac dispatcher and its poison-event and at-most-once hazards; an
  agent-manifest namespace change and the targeted subscription a manifest recompile would delete; a data migration of
  existing subscription rows.

## Risks & Assumptions

| # | Risk | Severity | Mitigation |
|---|------|----------|------------|
| 1 | A hook pointed at Omni before `connector.>` has a stream gets 500 on every delivery and GitLab disables it permanently after 40. | High | Slice 1 adds the subject; before any provider hook points at the per-connector route in production, stream info or one authenticated test delivery shows a stream holding `connector.>`. |
| 2 | Making the target optional before the guard lands fans a typed event out to every tenant's automations. | High | The guard and the D7 gate widening land first, proven with two tenants. |
| 3 | A connector event carries the body twice, so a large GitLab push reaches NATS `max_payload` at about half the body size and gets a non-2xx that counts toward the 40. | Medium | Typed rows carry the body once (Decisions #20), with ClickUp `connector.event` rows unchanged; a slice 1 test publishes a typed row whose body is above half of `max_payload`. |
| 4 | A `connector.*` row forged by a publisher other than the ingress (an automation `emit_event`, `/events/trigger`, a retried or replayed dead letter, including one stored before slice 1) carries a chosen target list, fires a targeted automation in any tenant whose id is known, and is journaled where consumers take it as provider-originated. | High | Decisions #22 and #23: `publishGeneric` refuses `connector.*` and only `publishConnector` publishes it; `emit_event` refuses it before its gates and writes no dead letter; manifests keep refusing it; the trigger route's `custom.`-only rule (`webhooks.ts:180-185`) is kept unchanged; retry and replay take routing only from the ingress-written journal row and refuse a dead letter without one. All land before the registry widens, each with a refusal test. |
| 5 | A per-connector subscription id posted to the per-subscription route, or a ClickUp row read as a per-connector one, journals or fires on the wrong route. | Medium | The `ingress` column and its CHECK (Decisions #24); the per-subscription route treats a `'connector'` id as unknown, with a wrong-route test and a CHECK test. |
| 6 | Two credentialed ingress paths coexist: signed webhook sources keep their own verification and `custom.` types beside connectors, and new ones are still accepted. | Medium | Settled R11-1 bounds it: signed sources keep working unchanged until the `signed-source-migration` brainstorm lands, and that brainstorm reaches "webhook sources remain only for credential-less ingress". Webhook sources cannot publish `connector.*` (they build `custom.` types, and `publishGeneric` refuses `connector.*`), so they cannot pose as a connector meanwhile. |
| 7 | The receiving `signed-source-migration` brainstorm does not exist yet, so the handed-over findings and Settled answers have no home. | Low | Nothing in slices 1, 2 or 4 depends on it, and R11-1 fixes what holds until it lands; the DRAFT lists what it inherits for whoever opens it. |
| 8 | GitLab header names (`webhook-id`, `Idempotency-Key`, `webhook-signature`) come from docs; whether a test delivery is signed is unconfirmed. | Low | Before cutover one real and one test delivery are captured; the zero-event proof does not depend on test deliveries. |

## Success Criteria

- [ ] **Slice 1, real NATS.** A test against a real NATS server, not the in-memory bus, publishes `connector.event` and `connector.gitlab.merge_request.merged` through an events-only, hook-secret-only fixture connector and reads each back from a durable consumer and the journal. **Proof:** a new real-NATS test under `packages/api/src/__tests__/` passes in the gate.
- [ ] **Slice 1, SDK rule.** A manifest with events and no actions registers; a manifest with no events is still refused; a hook-secret-only connector stores a sealed empty credentials object with the column NOT NULL. **Proof:** registry tests in `packages/connector-sdk/` and a sealed-credentials test in `packages/api/`.
- [ ] **Slice 1, no-target guard.** A `connector.event` and a typed connector event with no target fire no automation, in a test with two tenants. **Proof:** an engine and ingress test in `packages/core/src/automations/` and `packages/api/src/__tests__/`.
- [ ] **Slice 1, ClickUp unchanged.** An existing ClickUp subscription, its URL, secret, idempotency key and bound automation behave byte-for-byte as before: after migration 0091 the row reads `ingress = 'subscription'` and keeps its secret; it still accepts a target whose trigger is `connector.event`; its row keeps the single `subscriptionId`, `targetAutomationId` and `rawPayload`; its target fires once while another enabled `connector.event` automation in the tenant does not; and a ClickUp body carrying `targetAutomationIds` is journaled unchanged and fires only its bound automation. **Proof:** a regression test beside `packages/api/src/__tests__/connector-ingress-postgres.test.ts`.
- [ ] **Slice 1, route discriminator.** Posting a `'connector'` subscription id, such as a no-target row, to the per-subscription route journals nothing and fires nothing; the CHECK refuses a `'connector'` row with a secret and a `'subscription'` row without one. **Proof:** a Postgres ingress test and a schema test.
- [ ] **Slice 1, typed targets.** On the per-connector route, a targeted subscription on `connector.gitlab.merge_request.merged` whose automation holds that trigger fires it once per delivery; a targeted subscription with a glob, or with a target whose trigger is `connector.event` or another name, is refused naming both; a delivery matching two targeted subscriptions writes one row whose `targetAutomationIds[]` lists both and fires each once, and an automation holding the same trigger but named by no matched subscription does not fire. **Proof:** an engine test in `packages/core/src/automations/` for membership and a Postgres ingress test.
- [ ] **Slice 1, body once.** A typed row has no `rawPayload` key and carries the provider fields once at the top level; a typed delivery whose body is above half of NATS `max_payload` and below it less the envelope is journaled, published and answered 2xx. **Proof:** a real-NATS test under `packages/api/src/__tests__/`.
